# Auditoría de Ingeniería — Release 0.5.0 completa (`main...develop`)

- **Fecha:** 2026-11-02
- **Alcance:** todo lo que entra en producción con 0.5.0: `gitea/main` (`01c66b2`, v0.4.15) → `develop` (`83d1dbb`).
  111 commits, 418 ficheros (+57.059/−3.853, la mayoría snapshots, specs y plantillas).
- **Score:** **4.70 / 5.00 🟢 — apta para producción**, con un paso obligatorio antes del merge (H-R01) y una
  verificación posterior al despliegue (§7).
- **Responsable:** Claude Code (Opus 5.5).

## 1. Contexto y método

Qué entra en 0.5.0:
- **Fases del frontend modular:**
  - fase 0: XSS de Inicio;
  - fase 1: layouts y macros;
  - fase 2: JS a módulos ES, CSP `script-src 'self'`;
  - fase 3: CSS sin estilos inline, CSP `style-src 'self'`;
  - fase 4: plantillas OOB, `UIContext` y sidebar data-driven;
  - fase 5a: plantillas a `features/<dominio>/`;
  - fase 5b: consultas fuera de los routers.
- **Copiloto:** PAE-015 (`sales_by_location_monthly`), tool `product_movements` y rangos de fecha del prompt.
- **3 bugs de producción** corregidos en la fase 4.

Cada fase ya tiene su auditoría (4.35-4.95 tras corregir). Esta audita lo que ninguna ve sola: **preparación del
despliegue, diferencias producción/dev, hallazgos que se arrastran entre fases, seguridad transversal y código
muerto acumulado**.

| Herramienta | Uso |
|---|---|
| Serena | `find_symbol(include_body)` de `_static_asset_version`, `_agent_llm_ok`, cuerpos de handlers. |
| codebase-memory | Reindexado en `develop`; `search_graph` de funciones de `app/` con grado de entrada 0 (solo librerías vendoreadas y un manejador de evento JS: **sin código muerto propio**). |
| AST (script) | Barrido de los 123 handlers UI: guardia de rol por handler, contrastado con la matriz de permisos de la fase 4. |

| Producción (solo lectura) | `GET /ui/login` y `/health` públicos: cabeceras, scripts inyectados por Cloudflare, estado. |
| Ejecución real en `develop` | `pytest tests/unit` **539** · `ui_snapshot.py check` **91** · `pytest tests/e2e -m e2e` **95** · `style_snapshot.py check` **0 diferencias** · eval del copiloto 96/100/100 % · staging probado como admin/owner/operador (94 comprobaciones) y la tool por el chat real. |
| `grep`/lectura (fuera de cobertura) | Workflow de CD, `.bumpversion.cfg`, auditorías de fase, JS (`core/content.js`, `features/transfers.js`). |

pudieron inspeccionar (sin credenciales; H-R06).

## 4. Hallazgos

### 🟡 Medios

| ID | Título | Dim. | Evidencia | Riesgo | Recomendación |
|---|---|---|---|---|---|
| H-R01 | `main` tiene un commit que `develop` no tiene | 8 | `2f17200 docs: add roadmap of 7 evolution opportunities` (directo en `main`): `docs/roadmap/` no existe en `develop`, aunque `CLAUDE.md` lo cita. Merge en seco `develop` ← `main`: 0 conflictos. | Sorpresa al mergear y documentación desaparecida en `develop`. | **Antes del merge a `main`:** `git merge gitea/main` en `develop`, probar y después `develop → main`. |
| H-R02 | El healthcheck dice `agent_llm: degraded` en producción en falso | 7 | `app/routers/health.py:47-60`: `urlopen(f"{base}/models")` sin cabecera `Authorization`; la API externa responde 401 → "degraded". Visible hoy: `/health` de prod `"agent_llm":"degraded"`. Abierto desde 2026-08-17. | Una caída real del LLM no se distingue en monitorización. | Enviar `Authorization: Bearer <AGENT_LLM_API_KEY>` si hay key + test. Quick win. |

### 🟢 Bajos

| ID | Título | Dim. | Evidencia | Riesgo | Recomendación |
|---|---|---|---|---|---|
| H-R03 | `/csp-report` lee el cuerpo entero antes de comprobar su tamaño | 4 | `app/routers/csp_report.py:73-74` (`await request.body()` y luego `len(raw) > MAX_BODY_BYTES`). Endpoint público. | Un cuerpo enorme ocupa memoria antes del 413. | Rechazar antes por `Content-Length` (y leer en streaming con tope). |
